# Implementation Plan: Launch Pending Session Card

**Branch**: `069-launch-pending-card` | **Date**: 2026-05-06 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/069-launch-pending-card/spec.md`

## Summary

When the user clicks "Launch with Argus" in the dashboard and the server successfully opens a terminal, a placeholder session card with a spinner must appear immediately in the repository's session list, giving instant feedback that a launch is in progress.

The implementation has two halves:

- **Backend**: The `launch-terminal` endpoint generates a `ptyLaunchId` (UUID) before opening the terminal, passes it to the launcher process via `--launch-id` CLI argument, and returns it in the 202 response body. When a pending launcher WebSocket disconnects without claiming a session, the server broadcasts a `launcher.pending.gone` event carrying the `ptyLaunchId`.

- **Frontend**: `launchInTerminal()` returns the `ptyLaunchId` from the 202 response. A `usePendingLaunchers` hook stores transient placeholder records. `RepoCard` renders `PendingSessionCard` components for any pending launchers under that repo. The placeholder is removed when (a) a `session.created` WebSocket event arrives with a matching `ptyLaunchId`, (b) a `launcher.pending.gone` event arrives, or (c) a 30-second timeout fires.

## Technical Context

**Language/Version**: TypeScript 5 (strict), Node.js 22, React 18  
**Primary Dependencies**: Fastify 5, better-sqlite3, React Query v5, vitest, @testing-library/react, Playwright, ws, Tailwind CSS  
**Storage**: Backend: SQLite (no new tables — pending state is transient). Frontend: React in-memory state only.  
**Testing**: vitest (backend unit + integration, frontend unit + component), Playwright (e2e)  
**Target Platform**: Windows / macOS / Linux, single-user localhost developer tool  
**Project Type**: Full-stack web application (Fastify backend + React SPA)  
**Performance Goals**: Placeholder appears within 500ms of click (SC-001). Placeholder removed within 2s of `session.created` (SC-002).  
**Constraints**: No backend persistence for pending state. No new database migrations. No new npm packages.  
**Scale/Scope**: Single local user; up to ~10 concurrent sessions expected.
