# Tasks — 067 Session Update Noise

## Phase 1: Fix duplicate session.updated broadcasts from activity updates

- [X] T131 Fix duplicate `session.updated` broadcasts caused by `applyActivityUpdate()` bypassing `lastEmittedSessions`. Root cause: `applyActivityUpdate()` in `backend/src/services/watcher-session-helpers.ts` updates `lastActivityAt` in the DB and calls `broadcast()` directly, but never updates `lastEmittedSessions` in `SessionMonitor`. Because `sessionSignature()` in `backend/src/services/session-monitor.ts` includes `lastActivityAt`, the next scan cycle (~5s later) sees the changed signature and fires `monitor.emit('session.updated')` — a second identical broadcast to the frontend, plus a no-op Teams/Slack update. Fix: Remove `lastActivityAt` from `sessionSignature()` and add `yoloMode` (which is already tracked by `SessionDiffTracker` but was missing from the scan dedup). The signature fields after fix: `status, model, pid, hostPid, pidSource, launchMode, summary, yoloMode, endedAt`.

## Phase 2: Fix resting state not delivered to Teams/Slack

- [X] T132 Fix resting transition not reaching Teams/Slack integrations. Root cause: the resting block in `SessionMonitor.runScan()` (`backend/src/services/session-monitor.ts` ~line 443) calls `broadcast()` directly to the WebSocket, bypassing `monitor.emit('session.updated')`. Teams/Slack listeners subscribe to the monitor's `session.updated` event (via `server.ts`), so they never see the resting transition. Fix: (a) Add `isResting?: boolean` to the `Session` interface in `backend/src/models/index.ts` and `frontend/src/types.ts`. (b) In the resting block, replace `broadcast(...)` with `this.emit('session.updated', { ...session, isResting: true })` — the existing `server.ts` `monitor.on('session.updated', ...)` handler calls `broadcast()`, so the frontend continues to receive it. (c) In the activity-resumed branch (`else` block of the resting check), emit `this.emit('session.updated', { ...session, isResting: false })` only when removing from `restingNotifiedSessions` (guard with `has()` before `delete()`). (d) In `backend/src/services/session-diff-tracker.ts`, add `isResting: boolean` to `TrackedState`, add `{ key: 'isResting', label: 'Resting' }` to `TRACKED_FIELDS`, update `extract()` to map `session.isResting === true` (undefined → false), add `case 'isResting'` to `format()` returning `'yes'/'no'`, and update `update()` to skip the `isResting` comparison when `session.isResting === undefined` (DB sessions don't carry the field) while preserving the existing baseline `isResting` in those cases — this prevents regular scan-based emits from spuriously flipping the resting state in the baseline. Note: `isResting` is NOT added to `sessionSignature()` (it is not a DB field; the resting/un-resting emits happen outside the scan dedup loop and do not cause double-fires).
